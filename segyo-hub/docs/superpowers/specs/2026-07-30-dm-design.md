작성일: 2026-07-30
브랜치: feat/profile-phase2a

## 결정 사항 (브레인스토밍)

- 실시간: **Supabase Realtime** (messages INSERT 구독).
- DM 범위: 상대가 **친구(accepted)** 또는 **관리자(admin)** 이거나 내가 관리자. (특정 역할은 추후 can_dm에 추가.)
  대화가 생기면 이후엔 양쪽 자유롭게 주고받음.
- 안읽음: conversation_reads.last_read_at 기준.

## 데이터 모델 — `0018_dm.sql`

- `conversations(id, user_lo uuid, user_hi uuid, created_at, last_message_at,
   unique(user_lo,user_hi), check user_lo<user_hi)` — 1:1 쌍당 1개(uuid 정렬 정규화).
- `messages(id, conversation_id→conversations, sender_id, body text(1..2000), created_at)`.
- `conversation_reads(conversation_id, user_id, last_read_at, pk(conversation_id,user_id))`.
- `can_dm(other uuid) → boolean` (security definer): member+ 이고 (other=친구 or other=admin or 나=admin).
- `get_or_create_conversation(other uuid) → bigint` (security definer): can_dm 통과 시 정규화 쌍으로
  upsert 후 id 반환.
- 트리거: messages insert → conversations.last_message_at 갱신.
- RLS: conversations/messages/conversation_reads 모두 **참여자 본인만**. conversation insert는
  RPC(definer)로만. messages insert는 sender=본인 & 참여자.
- 실시간: `alter publication supabase_realtime add table public.messages` (postgres_changes가 RLS 적용).

## `lib/dm.ts` (순수, 테스트)
- `isConversationUnread({lastMessageAt,lastReadAt,lastSenderId}, myId)`.

## 화면
- `/messages` 받은편지함: 대화 목록(상대, 마지막 메시지, 시간, 안읽음 점), last_message_at desc.
- `/messages/[id]` 대화창: 초기 메시지 로드 + `<DmThread>`(realtime 구독, 전송, 열 때 읽음, 자동 스크롤).
- `/u/[id]`: can_dm이면 "메시지" 버튼 → get_or_create_conversation → /messages/[id].
- TopBar 메뉴에 "메시지".
